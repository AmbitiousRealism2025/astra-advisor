Astra Advisor

Keep implementation in your Pi/PiBB conversation. Have Astra inspect the result in a persistent tmux session, then have Sol handle GitHub Codex review through to an explicit clean result.

Who does what?

ModelResponsibility
Sol MediumCoordinates, waits for review, and reports results or decisions needed.
Astra HighGives planning advice from a focused brief, without tools.
Luna HighHandles narrow initial implementation.
Sol HighHandles complex implementation and all corrections requested by either reviewer.
Astra Medium in tmuxReads code and diffs. Retains its own Pi conversation across corrective rounds.

Medium and High are reasoning-effort settings, not guarantees of correctness. The model mapping uses openai-codex.

Review locally before publishing

Sol gathers evidence, implements, runs checks and inspects the diff. It then sends Astra an explicit review packet with scope, restrictions and test results.

Astra can read permitted files, search code and inspect fixed Git queries. Sol validates its findings, fixes confirmed blockers, tests again and returns the corrections to the same reviewer conversation.

Astra reviews; Sol fixes. The reviewer cannot edit files, run shell commands or tests, publish code, or grant approval.

The local loop has no fixed three-round ceiling. Identical evidence, disagreements, necessary deferrals, cancellation and operational failures stop without approval. Per-round resource limits still apply.

GitHub review

Request review of the exact commit

  1. Obtain publication permission. Activation is not permission to publish private code or unrelated work.
  2. Commit the intended change on a feature branch. The publication tool checks that the committed evidence still matches the clean local review and the current PR base.
  3. Push and open the PR. The tool uses the explicit repository matching origin, pushes without force, creates or updates the PR, and posts @codex review for the exact head.
  4. Wait for Codex. Findings return to Sol High. Sol fixes, tests, commits and requests review of the new head. Corrections stay in the main Pi/PiBB session.
  5. Report the reviewed PR. Finish only when trusted Codex feedback explicitly clears the latest requested commit. The extension never merges.

Pending is not clean

A matching clean message from the Codex bot, or its thumbs-up on the exact request, can establish clearance. Current-commit findings take precedence. The local and remote head/base must still match.

Silence, an eyes reaction, a generic completed summary, stale feedback and a polling timeout remain pending. Authentication, API, usage and changed-target problems pause the loop for attention.

No forced approval. Neither a stopped retry loop nor a return to Sol Medium means the work passed. A clean result is evidence from a model review, not certification or permission to merge.

Necessary fixes stay necessary

A correctness, security or compatibility problem cannot be cleared simply by calling it a separate task. Optional independent work may be proposed, but scope expansion and disagreements need your decision.

GitHub must have the Codex integration configured. Remote writes can succeed before a timeout; retry the recorded publication to reconcile it rather than creating duplicate requests.

Getting started

Install and activate

pi install git:github.com/AmbitiousRealism2025/astra-advisor

Reload or restart the Pi backend after installation. Do not load a manual copy and the package together.

/reload
/astra-advisor
/astra-advisor Investigate and fix the failing tests.

In a GUI that passes ordinary prompts to Pi:

Use /astra-advisor to investigate and fix the failing tests.

Look for “Astra Advisor active.” The GUI must render Pi custom messages to show the acknowledgment and review updates.

Check, stop or reset

/astra-advisor status
/astra-advisor off
/astra-advisor reset-review

Status shows saved pipeline state, not a fresh GitHub poll. Off cancels pending work but cannot undo completed remote writes. Reset authorizes a new cycle and closes only the owned tmux session; previous reports, artifacts and PRs remain.

Requirements and limits

  • Pi 0.85.1 is the tested version on Linux. Git, tmux, Node, Pi CLI, configured model access and authenticated GitHub CLI are required. Windows is unsupported.
  • Keep secrets out of briefs and readable source. Filename exclusions are not secret detection. Reviewer tools are restricted, but the extension is not an OS sandbox.
  • The reviewer’s conversation and logs persist under Pi’s agent directory. Do not publish raw session files or unsanitized logs.
  • Repeated reviews add time and usage. Tests and live-provider checks are different evidence; consult the development guide for current validation.
