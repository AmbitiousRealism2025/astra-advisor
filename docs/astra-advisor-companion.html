Astra Advisor

Use Sol to manage your task, ask Astra for advice, and have Astra inspect the finished work.

Astra Advisor is an add-on for the Pi coding agent. You turn it on when you want this model-switching approach. You keep working in the same conversation.

Who does what?

Model and settingIts job
Sol MediumStarts the task, gathers context, and reports the result or asks you to resolve an outstanding decision.
Astra HighGives planning advice. After implementation, it can inspect code and diffs with read-only tools and identify problems.
Luna HighHandles narrow, clearly defined implementation work and corrections.
Sol HighHandles complex, uncertain, or higher-risk implementation work and corrections.

“Medium” and “High” are reasoning-effort settings. They are not guarantees of correctness.

Advice first, evidence review afterward

Planning advice uses a focused brief. Astra has no tools at this stage. The executor then makes the change, runs checks and inspects the diff.

For the final review, Astra gets read-only access to the current workspace. It can read files, search code, inspect changes and look at recent Git history. It checks the implementation against the goal, intended behavior and reported test results.

Astra reviews; Sol or Luna fixes. The reviewer cannot edit files, run shell commands or tests, deploy anything, or grant approval.

The policy requires review for protocol, data-storage, authentication, package, session-lifecycle and release work. Routine low-risk review is optional. Model judgment still determines when to call the review tool.

The review loop

Fix important problems, then stop

Astra classifies each finding and explains the evidence. The extension uses that report to choose the next step.

Review resultWhat happens next
No blocking issuesReturn to Sol Medium for the final report. Minor follow-up suggestions can remain.
Fixes or evidence neededReturn to Sol or Luna High. It checks the findings, makes confirmed fixes, runs affected checks and requests another review.
Incomplete or disputedReturn to Sol Medium with the unresolved findings and reasons. Ask you for a decision when necessary.

What gets fixed now?

Problems that prevent the requested change from working safely are blockers. Examples include broken behavior, security mistakes, data loss or incompatible interfaces.

An unrelated existing problem or optional improvement can become a separate-task proposal. A large necessary fix is still blocking: the agent must ask before expanding the scope. It cannot turn a failed review into a pass by deferring that fix.

How the loop stays bounded

  • Three review rounds at most: the initial review and up to two corrective re-reviews.
  • Focused rechecks: Astra follows the same finding IDs and examines the corrections rather than starting from scratch.
  • No identical-evidence repeats: unchanged files and test evidence stop another review request.
  • No forced approval: limits, disagreements, cancellation and unresolved evidence return an incomplete result. They never count as a pass.
Returning to Sol Medium means you get control and a report. It does not mean the work passed verification.

The main agent drives fixes and rechecks; code enforces review-state transitions and limits. A pass means no blocking findings in inspected evidence, not proof that all bugs are gone. Astra does not independently run the reported tests.

Getting started

Turn it on when you need it

After installation or an update, reload or restart Pi. In the Pi terminal interface:

/reload
/astra-advisor

You do not need to add on. To activate and start a task:

/astra-advisor Investigate and fix the failing tests.

In a GUI that sends prompts to Pi, start your prompt with:

Use /astra-advisor to investigate and fix the failing tests.

The extension emits “Astra Advisor active”, plus review-start and outcome messages. A GUI must support Pi custom messages to display them.

Check, stop or start a fresh review cycle

/astra-advisor status
/astra-advisor off
/astra-advisor reset-review

It stays enabled for the session until turned off. Use reset-review when you authorize a new cycle for another task, or a retry after an incomplete review. Previous reports stay in history. Resetting does not mean verification passed.

What to keep in mind

  • Keep secrets out. Astra sees the supplied brief and files it reads. Common secret paths are blocked, but credentials hidden in ordinary source or logs may still be exposed.
  • Expect some extra time and usage. Reviews make model requests. You can cancel them normally; there is no background worker team.
  • Keep testing and reviewing. Read-only inspection cannot replace tests, your approval or external code review. Changed evidence can invalidate an earlier pass.

Uses existing Pi authentication and the openai-codex model mapping. Turning it off does not change global defaults. The reviewer is restricted to the current workspace, not arbitrary files elsewhere on your machine.

To recreate it: give a Pi agent astra-advisor-pi-extension.md.
